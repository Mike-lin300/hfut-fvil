## 三、问题清单与整改建议（按严重程度）

### 🔴 高优先级（上线运营前处理）

**1. Gunicorn 以 root 运行**
- 位置：`/etc/systemd/system/gunicorn.service` 的 `User=root`（交接文档 §四.4）
- 风险：Django 代码一旦存在可利用漏洞，攻击者获得的是 **root（最高权限）**，可读写整个服务器。
- 修复：
  ```ini
  # gunicorn.service 中改为
  User=www-data
  Group=www-data
  ```
  注意 `/var/www/hfut-fvil` 及 socket 目录权限需让 www-data 可读写（当前 `chmod 755 -R` 恰好已放开读；media/ 写入需 `chown -R www-data:www-data media/`）。

**2. 项目目录整体 755，`.env` 暴露**
- 位置：`chmod 755 -R /var/www/hfut-fvil`（交接文档 §四.6）
- 风险：`.env`（含 SECRET_KEY、DB 密码）被设为**所有用户可读**。
- 修复：`sudo chmod 600 /var/www/hfut-fvil/.env`（仅属主可读写）。

**3. HTTP 明文传输，无 HTTPS**
- 位置：全站 `http://<IP>/`
- 风险：后台登录密码、管理操作在公网明文传输，可被中间人截获。
- 修复：绑定域名后申请免费证书（Let's Encrypt / 阿里云免费 SSL），Nginx 加 443 监听 + 80 跳转；安全组放行 443。

### 🟡 中优先级（尽快处理）

**4. MySQL 密码沿用本地弱密码**
- 现状：库账号密码与本地开发一致（`fv_admin_2026`），且已出现在多份对话/文档文本中。
- 风险：虽然 3306 未对公网开放，但该密码已被记录在多个地方；系统被突破后等于直取数据库。
- 修复：`ALTER USER 'fvil'@'localhost' IDENTIFIED BY '<强随机密码>';` → 同步改服务器 `.env` 的 DB_PASSWORD → `sudo systemctl restart gunicorn`。

**5. SSH 密码登录暴露公网（22 对 0.0.0.0/0）**
- 风险：公网机器 24 小时被暴力破解扫描，弱密码有被撞库风险。
- 修复（按顺序做）：
  1. 阿里云控制台生成密钥对并绑定（或 `ssh-keygen` 后把公钥写入 `~/.ssh/authorized_keys`）；
  2. 测试密钥能登录后，`/etc/ssh/sshd_config` 设 `PasswordAuthentication no`，重启 sshd；
  3. 可选：安全组把 22 的来源限制为常用 IP；安装 `fail2ban`。

**6. 交接文档含明文密码**
- 位置：交接文档 §三 "密码 fv_admin_2026"
- 风险：该文本将复制给后续指导 AI/协作者，密码持续扩散。
- 处理：交接/文档一律用 `<数据库密码>` 占位符；真实值只存在于服务器 `.env`。

### 🟢 建议项

**7. 删除安全组 RDP 3389 规则**（Linux 用不到，减少攻击面）。
**8. 数据库账号最小权限**：当前 `GRANT ALL PRIVILEGES ON fvil.*`，可收缩为 Django 需要的常规权限（保留 DDL 以满足 migrate，折中可接受；如需严格最小化需另行评估）。
**9. 上线前补齐本地数据**：服务器是全新库 + 空 `media/`，需从本地迁移：`media/teachers/`（老师照片）、正式内容（后台录入）。测试数据无需迁移。

## 四、部署更新标准流程（后续开发循环）

```bash
cd /var/www/hfut-fvil
git pull                          # 拉取最新代码
source venv/bin/activate          # 进入虚拟环境
pip install -r requirements.txt   # 依赖有更新才需要
python manage.py migrate          # 模型有变更才需要
python manage.py collectstatic --noinput   # 静态文件有变更才需要
sudo systemctl restart gunicorn   # 每次代码更新后必须
sudo systemctl restart nginx      # Nginx 配置变更后
```

**黄金法则**：服务器只"跑"代码、不"改"代码（.env 除外）——所有代码修改在本地完成、提交推送后服务器 `git pull`。
